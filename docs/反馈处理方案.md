## 关于第 12 条

这条改的是**窗口模型**，不是某个界面：

- PRD FR-6.1 明确定义「待办是唯一的窄窗口视图（约 400×822）」，日历是 1000×700
- 现在两个视图靠 `window:setView` 切换窗口尺寸，M1–M5 的测试、`bounds.ts`、e2e 都建立在这个前提上

合并成「一个宽窗口 + 右侧停靠待办」意味着：

1. 窗口尺寸模型重写（只剩一个尺寸，或宽度可拉伸）
2. 顶部的 `日历 / 待办` 标签取消，换成「弹出待办」按钮
3. 「固定」按钮要求 `setIgnoreMouseEvents(ignore, { forward: true })`——鼠标穿透但滚轮可用，这是 Electron 的平台相关行为，需要实测
4. 相关 e2e（窗口尺寸断言）全部要改

**建议**：单独作为一个里程碑做（估计 6–8 个任务），而不是混在这批里。先确认要不要做、以及合并后窗口该多宽。
